# Decision registry

Every decision the FigDown specification cites, in one place. The normative text
cites these entries by **ID**; this file is what those IDs resolve to.

How the IDs are formed, what the statuses mean, and why this is one document
rather than a directory of files: [`README.md`](README.md). The short version —
an ID names **the topic, not the answer**, so it stays accurate if the ruling is
ever reversed, and it is UPPERCASE so that it cannot be mistaken for the
lowercase language it describes.

**This is a distillate, not a log.** Each row carries the ruling, its reason, and
the alternative that is still live. The full reasoning that produced a decision,
with its measurements and its dated history, is the project's working record and
is not published. What survives here is what a reader needs to understand the
language and to argue with it.

| Status | Means |
|---|---|
| `ruled` | decided and in force |
| `open` | a known question the language does not answer yet |
| `superseded` | replaced by another entry, named in the row |
| `defect` | a known deviation between the specification and an implementation |

**Completeness.** Every ID cited in published normative text has a row here, and
every row here is either cited from somewhere or says in its own row why it is
not. Both directions are checked by `tools/registry-check.js`, which runs in the
gate set — the claim has a mechanism rather than an intention. The normative genre-namespace rules — once numbered, now
`GENRE-NAMESPACE`, `GENRE-VOCABULARY-OBLIGATION`, `GENRE-COMPOSITION`,
`PER-GENRE-DEFAULTS`, `UNIVERSAL-CORE-KEYWORDS`, `DECLARATION-ORDER-SEMANTICS`
and `LAYOUT-ZONE-NAMESPACE` — are defined in [`spec/core.md`](../spec/core.md)
§1 and have rows here like everything else.

## Foundations

| ID | Status | What was decided | Why | Rejected alternative — and what would reopen it |
|---|---|---|---|---|
| `IMAGE-LOCKED-KNOWLEDGE` | ruled | FigDown exists to make knowledge that is locked inside document images machine-readable, while preserving the layout-based understanding a human gets from the picture. | Roughly half of real document images already suit a Mermaid-like syntax; the rest do not, and their layout itself carries meaning that a text form must not discard. | — |
| `TEXT-VERSUS-FIGURE-AUTHORITY` | ruled | (uncited: an axiom the README states in prose rather than citing) Text is the single source of truth; figures are deterministic rendering artifacts generated from it, with no separately maintained copy of the content. | Two audiences — agents and humans — must share one body of knowledge without duplicated near-synonymous copies. | — |
| `RENDERING-DETERMINISM` | ruled | Rendering is performed by a deterministic, non-model program, with a three-grade commitment: same source to same figure, local edit to local change, equivalent source to equivalent figure. | Mechanical renderability rules out fuzzy semantics that would need a model to interpret them. | — |
| `RENDER-AUTOMATION` | ruled | (uncited: an axiom the README states in prose rather than citing) The text-to-figure conversion is performed entirely by a tool, never by manual touch-up of the output. | The language must carry enough layout expressiveness that a tool alone, with zero hand-editing, produces a figure that looks hand-drawn. | Touching up rendered output as an escape hatch — rejected; any adjustment must be a declaration written in the text. |
| `LAYOUT-STABILITY` | ruled | Explicitly specified attributes always take priority over auto-layout, and a small change to the source must not produce a large change in the figure. | Readers hold a spatial mental map of a figure; a full re-layout triggered by one changed line destroys it. | — |
| `FIDELITY-TARGET` | ruled | The target is semantic fidelity — every component and relationship present and unambiguous — not pixel-for-pixel visual fidelity. | Text is a one-dimensional encoding of meaning; the acceptance bar is completeness of meaning, not visual replication. | — |
| `COMPLETENESS-DEFINITION` | ruled | The purpose is completeness of **meaning**, not completeness of **depiction**; a visual idiom earns a construct only if stripping it loses knowledge. Figure-plus-prose is the preferred authoring mode. | Depiction-completeness would make the standard an unbounded drawing toolkit — the exact failure the project exists to avoid. | Exclusions are falsifiable case by case rather than blanket. |
| `MEANING-RECOVERY-SOURCE` | ruled | A construct's meaning must be recoverable from the text alone without running the renderer; anything visible only in drawing geometry is presentation, and a reading agent must never infer meaning from it. | An audit found a bitfield row-wrap presentation detail that a naive reader could mistake for real bits. | — |
| `DESIGN-DECISION-METHOD` | ruled | Every design decision surveys existing standards first, prefers a small conservative feature set over invented special cases, and prefers generic rules over lists of special cases. | Mirrors protocol-standardization practice and keeps the rule count — and the cost of teaching the language to an agent — low. | — |
| `PRIOR-ART-BORROWING` | ruled | Where several existing conventions exist for a construct, adopt the one with the largest measured adoption. | Aligning with what a model already knows reduces syntax hallucination, since models autocorrect unfamiliar syntax toward their training dialect. | — |
| `AGENT-TEACHING-COST` | ruled | The prompt cost of teaching an agent the syntax is a hard design constraint: a small orthogonal core plus per-genre profiles, so an agent learns only the profile in use. | A lean authoring guide must suffice; requiring the full specification would make agent authoring impractical. | — |
| `DEFAULT-VALUE-SELECTION` | ruled | Every attribute's default matches the statistically most common real-world usage, and defaults are themselves normative. | An unadorned document should be correct as written; this shortens documents and maximises what the engine can adapt. | — |
| `UNDECLARED-ATTRIBUTE-BEHAVIOUR` | ruled | A declared extent is rigid and its content adapts to fit; an undeclared extent grows to fit content without disturbing the surrounding layout. | Generalises into the standard template for how any attribute behaves when left unspecified. | — |
| `SPELLING-LENGTH-VS-FREQUENCY` | ruled | The more common a usage, the shorter its spelling must be — from zero characters for the statistical default up to `key=value` for rare deviations. | Extends "defaults match the common case" from values to spelling, so common cases never pay syntax cost for a rare capability. | — |
| `PROJECT-NAME` | ruled | (uncited: a naming decision no normative sentence needs to cite) The project is FigDown (Figure + Markdown), with the `.fd` extension and the `figdown` fenced-block tag. | Reads as "the figure layer of Markdown" in one second, follows Markdown-family naming convention, and had no major collisions. | — |

## Document model and reading

| ID | Status | What was decided | Why | Rejected alternative — and what would reopen it |
|---|---|---|---|---|
| `TWO-READER-CONTRACT` | ruled | (uncited: an axiom the README states in prose rather than citing) An agent reads the source for meaning; a human reads the rendered SVG. The standard defines how the two stay paired and in sync. | One artifact serving two audiences is the project's central claim; without a defined pairing it degrades into dual maintenance. | — |
| `MARKDOWN-EMBEDDING-CONVENTION` | ruled | Until viewers render `.fd` natively, ship the source plus a generated SVG sidecar, embedded by a plain image reference with a `source:` footer. | Works in every existing Markdown viewer with zero ecosystem buy-in; the SVG carries its own source and hash so the pairing survives separation. | — |
| `CONTENT-LAYOUT-ZONE-SPLIT` | ruled | A document splits into a content zone that fully expresses the meaning and a trailing layout-only zone; a reading agent may stop at the zone marker. | Lets an agent skip rendering-only detail without losing any meaning. | — |
| `MEANINGFUL-ARRANGEMENT` | open | The skip guarantee is conditional on semantic completeness. Where position genuinely carries knowledge, the author must declare the arrangement load-bearing in prose and readers must then read the layout zone. | A closed language must not let position-as-knowledge hide in a zone readers are told to skip — that is ASCII art's core failure. | The spelling of a declared-arrangement construct is still open; this interim is a workaround for a missing construct, not a second contract. |
| `LAYOUT-ZONE-NAMESPACE` | ruled | The layout zone is its own namespace: no genre may define, redefine or extend any keyword inside it, whatever its status. | Skipping the zone is only safe if no genre semantics can ever appear inside it, and that guarantee was not previously in force. | Withdraws an earlier allowance letting a genre redefine zone members. |
| `READ-SIDE-DETERMINISM` | ruled | Two conforming implementations must derive an identical semantic model from the same source: duplicate single-valued directives error, edge form is preserved as written, absent labels are recorded as absent, and every default is written down. | Agents exchange meaning through source text, so parser-level ambiguity between faithful implementations defeats the purpose even without being a conventional bug. | — |
| `NORMATIVE-SEMANTIC-MODEL` | ruled | The semantic model and its JSON form are both normative — the model is the contract between reading and writing agents. | Previously the model existed only inside a tool's projection, so a second implementation had nothing but the reference engine's parse tree to match. | — |
| `OMITTED-LABEL-RECORDING` | ruled | An omitted label is recorded as absent, never materialised as the element's id; the renderer, not the model, substitutes the id for display. | A materialised default is legitimate only when it names something the author left to the language; substituting the id invents content and merges two distinguishable documents. | — |
| `EMPTY-LABEL-STATE` | ruled | An explicitly written empty label is a third state, distinct from both absent and text, preserved uniformly on every label-bearing directive; the renderer draws nothing for it. | A consumer testing truthiness rather than key presence would merge two distinguishable documents into one. | — |
| `EDGE-WRITTEN-FORM` | ruled | An edge is recorded exactly as written, with operator and endpoint order preserved; it is never rewritten to the reverse spelling. | Two spellings render identically but are not model-equivalent, because other constructs resolve an edge by its exact written form. | — |
| `REPEATED-DIRECTIVE-HANDLING` | ruled | Repeating a single-valued directive is a line error on the second occurrence, never silent last-one-wins. | A document stating two different values says two things, and a silent winner never tells the reader which was dropped. | — |
| `IDENTITY-ASSERTION` | open | The language has no way to assert that two elements are the same entity; sharing a class asserts a shared category, never an identity. | The need is real but no spelling has been settled, and a wrong one would license false equivalences. | — |
| `GENRE-REFERENCE-ADDRESS` | ruled | The concise per-genre reading files an agent needs in order to read a `.fd` correctly live at a versioned address of their own, `read/0.1/`, two hops from the repository root; a bundle that has to work with no repository around it vendors a copy that is generated from that address and byte-compared against it. | Reading a `bitfield` document costs the reading contract plus one genre file — an order of magnitude less text than the specification chapters that answer the same question — so the address should say *read this*, not *install this*, which is what a path inside an installable bundle says. A version directory makes the next language version an addition beside this one rather than an edit to it: archive behaviour with no archiving step, and an address that survives being quoted. | Leaving the files inside the bundle and pointing at them there — rejected; that path dangles for every reader who is not installing the bundle, and a second copy with no byte gate is a copy that drifts. Reopens if readers are measured arriving by a route the two-hop router does not serve. |

## Grammar and lexis

| ID | Status | What was decided | Why | Rejected alternative — and what would reopen it |
|---|---|---|---|---|
| `CLOSED-GRAMMAR` | ruled | Every non-blank, non-comment line begins with a registered keyword; unknown lines are errors carrying a 1-based line number. | This is what powers the agent write → validate → fix loop. A silently ignored line produces a figure that looks right and means something else. | — |
| `QUOTING-RULES` | ruled | Quoting splits into two questions: whether a position's grammar allows quotes at all (only string-typed positions do), and whether they are mandatory, which depends solely on the delimiter in use. | An unquoted multi-word value at a whitespace-delimited position is unparseable — the lexer cannot know where it ends. | — |
| `QUOTED-IDS` | ruled | A quoted token in any id position is a line error, with one wording across every id position. | Ids were handled inconsistently, most positions silently accepting quotes; the corpus showed zero legitimate uses. | — |
| `LINK-OPERATOR-IN-IDS` | ruled | The two-dash link-operator sequence may not appear inside any id, at any id position. | Any input admitting two legal readings must be reported as an error, never resolved by a greedy guess. Measured cost of the ban was zero. | — |
| `SEMICOLON-STATUS` | ruled | The semicolon is reserved for a possible future statement separator; a bare semicolon outside a quoted string, an edge label, a comment, or a table row is a line error naming the reservation. | The reservation had been stated too weakly and went unverified. The edge-label exemption is necessary — real documents use the character as ordinary punctuation there. | — |
| `POSITIONAL-LIST-SPELLING` | ruled | A comma-delimited single token is the sole spelling for positional lists; the space-separated forms are retired. | A rest-of-line list can never gain a trailing option and cannot be written down honestly without a terminator. Two forms accepting identical input gave authors two attractors with no signal for which was canonical. | A workload objection preserved both forms in an earlier round and was overridden on re-weighing. Auto-numbering was rejected outright. |
| `COMMA-LIST-WHITESPACE` | ruled | Every comma-delimited list is one whitespace-free token. | Trimming whitespace was rejected because whitespace is the only available terminator for a variable-length positional list; trimming would remove the ability ever to add a trailing option. | — |
| `OPTION-POSITION-PARSING` | ruled | Option position is free on every directive without exception. | Two directives tested quotedness on the raw token stream while reading values from the option-stripped stream, rejecting legal lines with misleading messages. A parser must not test one projection of a line and read from another. | — |
| `POSITIONAL-VS-NAMED-ARGUMENTS` | open | Whether a positional argument may also be written as a named option is unsettled. | Both spellings are defensible and the corpus has not yet shown which authors reach for. | — |
| `POSITIONAL-FLAG-SPELLING` | open | Whether bare positional flags should become option keys carrying a value is unsettled. | A flag can say only that something is true, never why — but converting them all has costs not yet measured. | — |
| `GRAMMAR-SKETCH-COMPLETENESS` | ruled | Every nonterminal used in the grammar sketch is defined in the specification or imported from the standard core rules; the sketch stays an explicit sketch, with per-directive arity and genre allowlists specified in prose. | An incomplete grammar sketch leaves implementers guessing about undefined nonterminals. | — |
| `TYPED-BLOCK-SILENT-FALLBACK` | ruled | Silent fallback, truncation and last-wins behaviours in typed-block parsing are explicit line errors instead. | Silent fallback contradicts the closed-grammar, no-silent-failure discipline. | — |

## Genres

| ID | Status | What was decided | Why | Rejected alternative — and what would reopen it |
|---|---|---|---|---|
| `FIGURE-TYPE-MECHANISM` | ruled | A figure's type is an application genre: one shared core grammar plus per-genre keyword meanings and defaults, drawn from corpus census buckets. | The same keyword needs a different default meaning per figure type, and a per-genre teaching unit keeps the cost of learning any one genre low. | — |
| `GENRE-NAMESPACE` | ruled | A genre defines its document's keyword namespace and may own keywords, or reuse another genre's spelling with a different meaning and different defaults. A genre never reinterprets another genre's document, and a small fixed core means the same thing everywhere. | Measurement across 141+ documents showed the six genres share almost no keyword usage in practice, so the earlier "every directive valid under every genre" promise was hollow. | Supersedes an earlier defaults-only limit, which was replaced once a genre owning nothing but defaults was found to add no real vocabulary. |
| `GENRE-VOCABULARY-OBLIGATION` | ruled | A genre MAY define keywords of its own, and MAY reuse another genre's spelling with a different meaning and different defaults — in exchange for documenting its complete vocabulary in its own normative genre document. | Ownership without a documentation obligation would make a keyword's meaning unknowable without reading an implementation. The exchange is what keeps the language closed while letting genres diverge. | — |
| `GENRE-COMPOSITION` | ruled | A document may compose genres: a nested genre region is governed by that genre's namespace, and its child keywords are not valid at the document's top level. Composition is not inheritance — the header genre does not acquire the nested genre's vocabulary. | Without the non-inheritance half, composing one genre into another would silently widen the host's allowlist and defeat the point of a per-genre namespace. | — |
| `PER-GENRE-DEFAULTS` | ruled | A genre's defaults need no justification beyond that genre's own corpus statistics, read per bucket rather than across the whole corpus. | A default that matches the common case globally can be wrong for every individual genre; the statistic that matters is the one for the figures the genre actually serves. | — |
| `UNIVERSAL-CORE-KEYWORDS` | ruled | Three keywords — the header, the title and the layout-zone marker — mean the same thing under every genre, and no genre may redefine them. | This is a **fixity** guarantee, not a ubiquity requirement: it does not say every document must use them, only that where one appears its meaning is fixed. It is what lets a reader skip the layout zone without first working out the genre. | — |
| `UNSAFE-DEFAULT-ELIMINATION` | ruled | A keyword whose spelling collides with an established meaning is renamed, and a default is legitimate only where being wrong is harmless — so the bitfield's bit-numbering direction became a required token with no default at all. | A name that collides costs the reader even when the parser is satisfied; and evidence showed the numbering default was actively, silently wrong on real documents. | — |
| `HEADER-GENRE-REQUIREMENT` | ruled | The header's genre token is required, and the header is the first **significant** line — comments and blank lines may precede it. | Three scene genres share one vocabulary and differ only in defaults, so the header is the only place such a document states what kind of figure it is; omitting it destroys that distinction with no recoverable fallback. | — |
| `GENRE-KEYWORD-ALLOWLIST` | ruled | Each header genre enforces an allowlist of legal top-level keywords: a small core plus the layout namespace always allowed, pure genres rejecting scene keywords, scene genres sharing one scene vocabulary. | Corpus measurement matched the split exactly, and an allowlist lets a future genre bring its own namespace without a major version bump. | — |
| `GENRE-EARNING-THRESHOLD` | ruled | A figure genre with a clear, well-defined interpretation method earns its own small closed vocabulary once generic constructs are shown to lose that interpretation method. | Approximating a genre with generic boxes and edges can look right while discarding genre-level meaning a reader cannot recover from geometry. | — |
| `DOMAIN-VOCABULARY-PREFERENCE` | ruled | A genre should introduce its own domain keywords for participants and relations rather than reusing generic ones. | A genre reusing only generic vocabulary delivers nothing beyond a generic document, defeating the point of earning a genre. | Whether some genres legitimately stay generic is left open per genre. |
| `GENRE-DOCUMENT-CONTRACT` | ruled | Each genre gets its own self-contained, terse document covering defaults, closed vocabulary, reading rules, errors and one example. | Mirrors the small-core-plus-on-demand teaching model: an agent learns the core plus one genre. | — |
| `LOGIC-FLOWCHART-GENRE-SCOPE` | ruled | Digital logic and flowchart are independent genres; logic gets a first-class construct family, and flowchart gets closed role vocabulary rather than inferring meaning from shape. | Gate and mux symbols are internationally standardised meaning-bearing symbols that a shape enum cannot honestly carry. | Expressing gates as shape-enum values was rejected because shape must stay purely geometric. Live until a genre-design session finalises spelling. |
| `FLOWCHART-GENRE-DESIGN` | open | The full flowchart genre design is not settled. | Role vocabulary landed first because it was the measurable gap; the rest needs a design session. | — |
| `FLOWCHART-ROLE-KEYWORDS` | ruled | `flowchart` gains experimental role keywords that desugar to a node plus a derived shape; an explicit shape override remains legal for drawing only. | A reader cannot recover role from a shape override, and the shape convention itself is followed inconsistently — only 78% of question-labelled nodes use the expected shape. | A two-keyword design defaulting a bare node to "process" was rejected because a flowchart node can also be a datastore, annotation or state. Reopens on measurement showing non-step nodes are vanishingly rare. |
| `FLOWCHART-ROLE-SOURCE` | ruled | **ISO 5807** is a **role** standard, not a geometry standard, which makes it an eligible source for the role keywords. | Every cited definition in it describes what a symbol represents, never its drawn form. | Two verification gaps stay open: one role's exact spelling pending full access to the standard, and whether unseen sections define symbols by drawn form. |
| `QUANTITY-EXTENT-GENRE` | open | A quantity-extent figure kind is filed as a genre candidate; the constructs serving it stay experimental rather than being promoted. | Corpus measurement found roughly 22 figure-identities needing named reference values and regions — a genre-shaped need that generic constructs only approximate. | — |
| `TIMING-GENRE-NAMING` | ruled | The experimental waveform genre is named `timing`. | The word it previously used is, in the source format, a member key of a signal rather than the figure's own name — so a whole genre had been named after another format's property key. | — |
| `BITFIELD-GENRE-NAMING` | ruled | The `bitfield` genre name is kept. | It is the borrowed diagram-kind name from its primary source; measured alternatives were worse fits. | — |
| `CHART-SCOPE-BOUNDARY` | ruled | The normative vocabulary excludes charting and plotting constructs; the fallback is the original raster image plus prose, or a `table` of values. | X-Y figures were about 1% of the measured corpus and scored zero on semantic completeness: a trend chart's knowledge is its values, and a table conveys them without loss. | The exclusion is falsifiable case by case. A proportional-area encoding is flagged as the first candidate that may pass the irreplaceability test where a trend chart does not. |
| `ELECTRICAL-SCHEMATIC-SCOPE` | ruled | Electrical-schematic symbols are permanently out of scope, and any out-of-scope raster figure must carry its knowledge in accompanying machine-readable text. | Schematics belong to a distinct design-automation domain a general documentation-diagram language should not absorb; the raster-fallback obligation enforces the founding goal that no figure keeps its picture while losing its readable knowledge. | — |
| `MULTI-FIGURE-DOCUMENTS` | ruled | A document may stack multiple sections, each with its own genre header, into one artifact. | Hybrid panels are common and composition beats inventing a hybrid genre. | — |
| `D2-RELATIONSHIP` | ruled | FigDown's relationship to **D2** is settled: borrow D2's spellings where they are the most-adopted convention — the edge operator set `->` `<-` `--` `<->` comes from it whole — and diverge only where the layout-stability commitment requires it. | Borrowing before inventing is the standing methodology, and D2 is the closest peer language by construct overlap. | — |

## Scene constructs

| ID | Status | What was decided | Why | Rejected alternative — and what would reopen it |
|---|---|---|---|---|
| `SHAPE-ENUM-VOCABULARY` | ruled | Node shapes are a small closed **geometric** enum; device or role meaning is carried only in the label text, never in a shape name. | Binding shapes to domain nouns is an endless list, and the meaning already lives in the label. A value naming a domain rather than a geometry was later found in the enum and removed. | Any proposed shape name must show it names a geometry, not a role. One callout use lost its spelling in the removal — a documented capability loss that reopens once a dedicated annotation construct lands. |
| `EDGE-LABEL-PLACEMENT` | ruled | Edge labels are written inside the arrow operator, at up to three inline positions — near the tail, on the line, and near the head. | No surveyed mainstream language offers more than three, and inline placement keeps a label's position in the text matching its position in the figure, on one line with the relationship it labels. | Separate tail/mid/head option keys were retired as redundant. |
| `EDGE-LABEL-OFFSET-CONTROL` | ruled | Finer edge-label position hints are rejected for the current language version. | Pure presentation, and they would invite pixel-level hand-tuning. | Reopens if real figures demand it; additions are cheap under the migration model. |
| `REVERSE-ARROW-OPERATOR` | ruled | A leftward arrow operator is supported alongside the rightward one. | Which side of a relationship an author names first is itself part of how humans encode meaning. | — |
| `ERD-EXPRESSION-LEVEL` | ruled | Entity-relationship diagrams are expressed with existing node, edge and group constructs — attributes as label lines, cardinality as endpoint labels — rather than a dedicated typed-entity construct. | Satisfies the survey-before-invent methodology while making the figure family immediately available with no new vocabulary. | Crow's-foot cardinality notation was rejected as drawing-shaped vocabulary duplicating meaning already carried by endpoint labels. A dedicated typed-entity construct stays a gated future candidate; reopens on evidence that endpoint labels are insufficient. |
| `EXTERNAL-EDGE-ENDPOINTS` | ruled | A first-class endpoint construct marks an edge that enters or leaves the figure from outside it. | Open-ended arrows appear in over 70% of a stratified sample, and the alternative would smuggle existential meaning into a geometric attribute. | An unrendered "none" shape value was rejected because shape must stay purely geometric. Reopens only if a future need requires drawing something beyond an unlabeled open line. |
| `EXTERNAL-ENDPOINT-NAMING` | ruled | The external-endpoint keyword is named so as not to collide with established diagramming terms that mean something opposite or unrelated. | The project's own prose had already stopped using the earlier word, glossing it every time it appeared. | Two alternatives were rejected for role connotation and for colliding with edge endpoints. |
| `EDGE-ENDPOINT-ELIGIBILITY` | open | Edges may terminate only on nodes and external endpoints; a construct distinguishing observation-only taps from true junctions is filed for a later version. Interim: an intermediate bus node. | Corpus evidence found 22+ figures where bus topologies get flattened to star and mid-wire taps become duplicate edges — both semantic errors. | Deferred to the holistic targeting and annotation design session. |
| `CELL-EDGE-ANCHORS` | open | Whether an edge may attach to a table or grid cell is unsettled. | Shares one design axis with the rest of the annotation family; ruling on it alone risks an inconsistent spelling. | — |
| `TAP-VERSUS-JUNCTION-SPELLING` | open | The spelling for mid-edge taps and junctions is unsettled. | A junction is real connectivity and a tap is not, and one construct must not blur them. | — |
| `EDGE-IDENTITY-AND-GEOMETRY` | open | The language cannot name an individual edge, and therefore cannot express a request about that edge's geometry. | This is the gap left by withdrawing the earlier edge-geometry constructs; addressing it needs an edge-identity construct first. | Reopens the withdrawn capability once the language can address an individual edge. |
| `EDGE-GEOMETRY-CONSTRUCTS` | ruled | Two experimental layout-zone edge-geometry constructs, and the option keys they carried, are withdrawn from the language entirely with nothing replacing them — the first outright withdrawal. | A source-graded study across **mxGraph, ELK, Visio and draw.io** found the realisation sat outside the narrow stable intersection those four share; a behaviour audit found them rarely used correctly, with zero downstream adoption. Removal measurably improved layout quality. | Keeping one of the two alone was rejected: its per-edge half has nothing to attach to. The underlying need is filed as `EDGE-IDENTITY-AND-GEOMETRY`. |
| `ENDPOINT-DOCKING-KEYS` | superseded | Option keys letting an author dock an endpoint at a compass point or fractional position on its target, spelled after the compass vocabulary of the standard that defines the concept. | Mirrored the degree of freedom mainstream editors offer for endpoint attachment. | Withdrawn with the construct they belonged to — see `EDGE-GEOMETRY-CONSTRUCTS`. |
| `WAYPOINT-KEY-SPELLING` | superseded | The waypoint option key was renamed to the ordered-coordinate-list spelling shared by two major systems. | The earlier spelling had zero attestation as a waypoint key anywhere surveyed. | Withdrawn with its construct — see `EDGE-GEOMETRY-CONSTRUCTS`. |
| `EDGE-LINE-SHAPE-KEYWORD` | superseded | An edge-line-shape keyword was kept unrenamed despite being a loaded word in networking. | No surveyed source supplied a better single word, and a two-value enum made the misreading impossible. | Withdrawn with its construct — see `EDGE-GEOMETRY-CONSTRUCTS`. |
| `ELEMENT-GEOMETRY-DIRECTIVE` | ruled | The separate size directive is retired and merged into the position directive, which now carries an element's declared position, width and height together; the old spelling is a line error naming its replacement. | The two always addressed the same element by the same id, forcing every consumer to rejoin two model arrays. Width and height apply only to nodes; groups and typed blocks derive size from content. | A `geometry` spelling was argued and rejected for zero directive-level attestation in any line-oriented diagram language. Reopens on genuine attestation elsewhere, or a comprehension study favouring it. |
| `PIN-COORDINATE-SCOPE` | ruled | A node's declared position inside a group is relative to the group's own origin; the group itself is anchored in absolute canvas coordinates. | Matches the two-level coordinate systems of mainstream layout frameworks, keeps a dragged group's edit to one line, and stops an edit in one group disturbing another. | — |
| `PIN-COORDINATE-UNITS` | ruled | Declared coordinates are in pixels relative to the positioning context. | The only unit the renderer can honour without a declared scale. | — |
| `GROUP-LEVEL-FLOW` | open | Whether a group may declare its own flow direction, giving side-by-side sub-areas inside one figure, is unsettled. | Real figures need it; the interaction with the parent's flow has not been designed. | — |
| `INDENTED-BLOCK-SUGAR` | ruled | Indentation-based block syntax is rejected. | It would be a second containment syntax alongside the existing one, and a closed grammar should have one way to say a thing. | — |
| `REPEATED-SUBGRAPH` | open | The language has no construct for a repeated subgraph or an instantiated template. | The need is attested but the spelling interacts with identity, which is itself open. | — |
| `NAMED-LANES` | open | Named lanes and semantic layering are unsettled. | Raised by field feedback; overlaps with grouping and with the plane construct. | — |
| `NON-GRAPH-ANNOTATION-NODE` | open | A node that annotates the figure without joining the graph has no spelling. | Modelling it as a real node adds a false participant to the relationship set. | — |
| `CONTIGUOUS-RANGE-GROUPING` | open | A named set over a contiguous range of fields, rows or nodes has no spelling. | Shares the annotation family's design axis; the range half is well understood, the annotation half is not. | — |
| `ANNOTATION-FAMILY-SEQUENCING` | open | Several annotation needs — per-row gutters, attached callouts, edge-attached notes, cell anchors and range grouping — are held as one design problem rather than ruled on individually. | They share one design axis, so ruling piecemeal risks inconsistent spellings. | A generic "text on any side of a node" construct was rejected: it would flatten a role-bearing annotation into undifferentiated text. |

## Process and evidence

| ID | Status | What was decided | Why | Rejected alternative — and what would reopen it |
|---|---|---|---|---|
| `NEW-CONSTRUCT-EVIDENCE-GATE` | ruled | A new keyword or genre is added only when a meaning has no chance of precise expression through existing constructs. Inserting the index inside the label would mean parsing an opaque label to find where it belongs, which no engine may do. | The strip beneath a single occurrence — rejected. Reopens if a primary source is found that draws a repeated run as one element plus a range annotation. |
| `ELISION-MARK-EXTENT` | ruled | The elision mark between the two occurrences of a repeated run draws a dotted line at each end only when the mark is narrower than the word. An element that fills the word gets an open strip. | The end lines say *which columns are elided*, which is real information for a narrower element — a 16-bit field's strip drawn without ends would leave the reader guessing how wide the elided thing is — and nothing at all for an element that occupied every column. The transcribed source prints the same row with no bar at either end. | An option key restoring the ends — rejected; the author names the meaning and the engine owns the drawing, and no reader benefits from a mark that marks nothing. Reopens if a genre needs a full-word element's elision distinguished from something else drawn the same way. |
| `ERROR-RECOVERY-MODEL` | open | Error **recovery** is unspecified: after a line error the parser's continuation is not defined, and the choice changes which later errors are reported at all. | Recovery determines the error **set**, so leaving it unwritten makes conformance goldens depend on unstated behaviour. Filed rather than ruled because fixing it means choosing a recovery strategy across every genre at once. | Reopens when a recovery strategy is proposed with its effect on the existing goldens measured. |
| `COLSPAN-EMPTY-CELL-SPELLING` | open | The table colspan is spelled by an empty raw segment between delimiters — an **invisible** distinction that a formatter aligning columns can silently destroy. | Written down with its hazard rather than changed: the spelling is load-bearing in the frozen surface and every alternative collides with the row syntax. Naming the hazard is what lets a downstream formatter be told about it. | Reopens if a non-invisible spelling is found that does not collide, or if a formatter is observed destroying one in the corpus. |
