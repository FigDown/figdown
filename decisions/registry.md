# Decision registry

Every decision the FigDown specification cites, in one place. The normative text
cites these entries by **ID**; this file is what those IDs resolve to.

How the IDs are formed, what the statuses mean, and why this is one document
rather than a directory of files: [`README.md`](README.md). The short version —
an ID names **the topic, not the answer**, so it stays accurate if the ruling is
ever reversed, and it is UPPERCASE so that it cannot be mistaken for the
lowercase language it describes.

**This is a distillate, not a log.** Each row carries the ruling, its reason, and
the alternative that is still live. The full reasoning that produced a decision,
with its measurements and its dated history, is the project's working record and
is not published. What survives here is what a reader needs to understand the
language and to argue with it.

| Status | Means |
|---|---|
| `ruled` | decided and in force |
| `open` | a known question the language does not answer yet |
| `superseded` | replaced by another entry, named in the row |
| `defect` | a known deviation between the specification and an implementation |

**Completeness.** Every ID cited in published normative text has a row here, and
every row here is either cited from somewhere or says in its own row why it is
not. Both directions are checked by `tools/registry-check.js`, which runs in the
gate set — the claim has a mechanism rather than an intention. The normative genre-namespace rules — once numbered, now
`GENRE-NAMESPACE`, `GENRE-VOCABULARY-OBLIGATION`, `GENRE-COMPOSITION`,
`PER-GENRE-DEFAULTS`, `UNIVERSAL-CORE-KEYWORDS`, `DECLARATION-ORDER-SEMANTICS`
and `LAYOUT-ZONE-NAMESPACE` — are defined in [`spec/core.md`](../spec/core.md)
§1 and have rows here like everything else.

## Foundations

| ID | Status | What was decided | Why | Rejected alternative — and what would reopen it |
|---|---|---|---|---|
| `IMAGE-LOCKED-KNOWLEDGE` | ruled | FigDown exists to make knowledge that is locked inside document images machine-readable, while preserving the layout-based understanding a human gets from the picture. | Roughly half of real document images already suit a Mermaid-like syntax; the rest do not, and their layout itself carries meaning that a text form must not discard. | — |
| `TEXT-VERSUS-FIGURE-AUTHORITY` | ruled | (uncited: an axiom the README states in prose rather than citing) Text is the single source of truth; figures are deterministic rendering artifacts generated from it, with no separately maintained copy of the content. | Two audiences — agents and humans — must share one body of knowledge without duplicated near-synonymous copies. | — |
| `RENDERING-DETERMINISM` | ruled | Rendering is performed by a deterministic, non-model program, with a three-grade commitment: same source to same figure, local edit to local change, equivalent source to equivalent figure. | Mechanical renderability rules out fuzzy semantics that would need a model to interpret them. | — |
| `RENDER-AUTOMATION` | ruled | (uncited: an axiom the README states in prose rather than citing) The text-to-figure conversion is performed entirely by a tool, never by manual touch-up of the output. | The language must carry enough layout expressiveness that a tool alone, with zero hand-editing, produces a figure that looks hand-drawn. | Touching up rendered output as an escape hatch — rejected; any adjustment must be a declaration written in the text. |
| `LAYOUT-STABILITY` | ruled | Explicitly specified attributes always take priority over auto-layout, and a small change to the source must not produce a large change in the figure. | Readers hold a spatial mental map of a figure; a full re-layout triggered by one changed line destroys it. | — |
| `FIDELITY-TARGET` | ruled | The target is semantic fidelity — every component and relationship present and unambiguous — not pixel-for-pixel visual fidelity. | Text is a one-dimensional encoding of meaning; the acceptance bar is completeness of meaning, not visual replication. | — |
| `COMPLETENESS-DEFINITION` | ruled | The purpose is completeness of **meaning**, not completeness of **depiction**; a visual idiom earns a construct only if stripping it loses knowledge. Figure-plus-prose is the preferred authoring mode. | Depiction-completeness would make the standard an unbounded drawing toolkit — the exact failure the project exists to avoid. | Exclusions are falsifiable case by case rather than blanket. |
| `MEANING-RECOVERY-SOURCE` | ruled | A construct's meaning must be recoverable from the text alone without running the renderer; anything visible only in drawing geometry is presentation, and a reading agent must never infer meaning from it. | An audit found a bitfield row-wrap presentation detail that a naive reader could mistake for real bits. | — |
| `DESIGN-DECISION-METHOD` | ruled | Every design decision surveys existing standards first, prefers a small conservative feature set over invented special cases, and prefers generic rules over lists of special cases. | Mirrors protocol-standardization practice and keeps the rule count — and the cost of teaching the language to an agent — low. | — |
| `PRIOR-ART-BORROWING` | ruled | Where several existing conventions exist for a construct, adopt the one with the largest measured adoption. | Aligning with what a model already knows reduces syntax hallucination, since models autocorrect unfamiliar syntax toward their training dialect. | — |
| `AGENT-TEACHING-COST` | ruled | The prompt cost of teaching an agent the syntax is a hard design constraint: a small orthogonal core plus per-genre profiles, so an agent learns only the profile in use. | A lean authoring guide must suffice; requiring the full specification would make agent authoring impractical. | — |
| `DEFAULT-VALUE-SELECTION` | ruled | Every attribute's default matches the statistically most common real-world usage, and defaults are themselves normative. | An unadorned document should be correct as written; this shortens documents and maximises what the engine can adapt. | — |
| `UNDECLARED-ATTRIBUTE-BEHAVIOUR` | ruled | A declared extent is rigid and its content adapts to fit; an undeclared extent grows to fit content without disturbing the surrounding layout. | Generalises into the standard template for how any attribute behaves when left unspecified. | — |
| `BOUNDED-GROWTH-ACCOMMODATION` | ruled | The growth clause above is amended a second time the same day, superseding its own first amendment. An undeclared extent still grows minimally to fit content, but the promise about what else may move is no longer *the surrounding layout is never disturbed* nor *only a node in the same rank may move* — both were measured false — and is instead: **an unnamed node may move, but never farther than the named node's own box grew.** | A same-rank version of the promise was tried first and refused by its own measuring instrument: regraded by rank, the same corpus pairs it was written to excuse still failed, because a label grows a box's width, and when the flow direction runs along that axis the growth is structurally a push into the next rank, never within its own — no same-rank wording can absorb that. Re-reading the same measurement for a different bound found what the engine already delivers: across every measured corpus pair, including every one that violates both the original promise and the same-rank one, no unnamed node ever moved farther than the named node's own box grew. | The original promise and the same-rank promise — both refused as false claims the corpus measured broken, the same defect class an unenforced vocabulary claim would be. An engine change making growth never displace anything at all — declined as real, undesigned, corpus-wide rendering work, not a change a ruling should make for free; it remains the path back to the original promise if it is ever built. A grown box rerouting a connector between two untouched nodes is a different, separately filed defect and is not this clause's claim. |
| `SPELLING-LENGTH-VS-FREQUENCY` | ruled | The more common a usage, the shorter its spelling must be — from zero characters for the statistical default up to `key=value` for rare deviations. | Extends "defaults match the common case" from values to spelling, so common cases never pay syntax cost for a rare capability. | — |
| `PROJECT-NAME` | ruled | (uncited: a naming decision no normative sentence needs to cite) The project is FigDown (Figure + Markdown), with the `.fd` extension and the `figdown` fenced-block tag. | Reads as "the figure layer of Markdown" in one second, follows Markdown-family naming convention, and had no major collisions. | — |

## Document model and reading

| ID | Status | What was decided | Why | Rejected alternative — and what would reopen it |
|---|---|---|---|---|
| `TWO-READER-CONTRACT` | ruled | (uncited: an axiom the README states in prose rather than citing) An agent reads the source for meaning; a human reads the rendered SVG. The standard defines how the two stay paired and in sync. | One artifact serving two audiences is the project's central claim; without a defined pairing it degrades into dual maintenance. | — |
| `MARKDOWN-EMBEDDING-CONVENTION` | ruled | Until viewers render `.fd` natively, ship the source plus a generated SVG sidecar, embedded by a plain image reference with a `source:` footer. | Works in every existing Markdown viewer with zero ecosystem buy-in; the SVG carries its own source and hash so the pairing survives separation. | — |
| `CONTENT-LAYOUT-ZONE-SPLIT` | ruled | A document splits into a content zone that fully expresses the meaning and a trailing layout-only zone; a reading agent may stop at the zone marker. | Lets an agent skip rendering-only detail without losing any meaning. | — |
| `MEANINGFUL-ARRANGEMENT` | open | The skip guarantee is conditional on semantic completeness. Where position genuinely carries knowledge, the author must declare the arrangement load-bearing in prose and readers must then read the layout zone. | A closed language must not let position-as-knowledge hide in a zone readers are told to skip — that is ASCII art's core failure. | The spelling of a declared-arrangement construct is still open; this interim is a workaround for a missing construct, not a second contract. |
| `LAYOUT-ZONE-NAMESPACE` | ruled | The layout zone is its own namespace: no genre may define, redefine or extend any keyword inside it, whatever its status. | Skipping the zone is only safe if no genre semantics can ever appear inside it, and that guarantee was not previously in force. | Withdraws an earlier allowance letting a genre redefine zone members. |
| `READ-SIDE-DETERMINISM` | ruled | Two conforming implementations must derive an identical semantic model from the same source: duplicate single-valued directives error, edge form is preserved as written, absent labels are recorded as absent, and every default is written down. | Agents exchange meaning through source text, so parser-level ambiguity between faithful implementations defeats the purpose even without being a conventional bug. | — |
| `NORMATIVE-SEMANTIC-MODEL` | ruled | The semantic model and its JSON form are both normative — the model is the contract between reading and writing agents. | Previously the model existed only inside a tool's projection, so a second implementation had nothing but the reference engine's parse tree to match. | — |
| `OMITTED-LABEL-RECORDING` | ruled | An omitted label is recorded as absent, never materialised as the element's id; the renderer, not the model, substitutes the id for display. | A materialised default is legitimate only when it names something the author left to the language; substituting the id invents content and merges two distinguishable documents. | — |
| `EMPTY-LABEL-STATE` | ruled | An explicitly written empty label is a third state, distinct from both absent and text, preserved uniformly on every label-bearing directive; the renderer draws nothing for it. | A consumer testing truthiness rather than key presence would merge two distinguishable documents into one. | — |
| `EDGE-WRITTEN-FORM` | ruled | An edge is recorded exactly as written, with operator and endpoint order preserved; it is never rewritten to the reverse spelling. | Two spellings render identically but are not model-equivalent, because other constructs resolve an edge by its exact written form. | — |
| `REPEATED-DIRECTIVE-HANDLING` | ruled | Repeating a single-valued directive is a line error on the second occurrence, never silent last-one-wins. | A document stating two different values says two things, and a silent winner never tells the reader which was dropped. | — |
| `IDENTITY-ASSERTION` | open | The language has no way to assert that two elements are the same entity; sharing a class asserts a shared category, never an identity. | The need is real but no spelling has been settled, and a wrong one would license false equivalences. | — |
| `GENRE-REFERENCE-ADDRESS` | ruled | The concise per-genre reading files an agent needs in order to read a `.fd` correctly live at a versioned address of their own, `read/0.1/`, two hops from the repository root; a bundle that has to work with no repository around it vendors a copy that is generated from that address and byte-compared against it. | Reading a `bitfield` document costs the reading contract plus one genre file — an order of magnitude less text than the specification chapters that answer the same question — so the address should say *read this*, not *install this*, which is what a path inside an installable bundle says. A version directory makes the next language version an addition beside this one rather than an edit to it: archive behaviour with no archiving step, and an address that survives being quoted. | Leaving the files inside the bundle and pointing at them there — rejected; that path dangles for every reader who is not installing the bundle, and a second copy with no byte gate is a copy that drifts. Reopens if readers are measured arriving by a route the two-hop router does not serve. |

## Grammar and lexis

| ID | Status | What was decided | Why | Rejected alternative — and what would reopen it |
|---|---|---|---|---|
| `CLOSED-GRAMMAR` | ruled | Every non-blank, non-comment line begins with a registered keyword; unknown lines are errors carrying a 1-based line number. | This is what powers the agent write → validate → fix loop. A silently ignored line produces a figure that looks right and means something else. | — |
| `QUOTING-RULES` | ruled | Quoting splits into two questions: whether a position's grammar allows quotes at all (only string-typed positions do), and whether they are mandatory, which depends solely on the delimiter in use. | An unquoted multi-word value at a whitespace-delimited position is unparseable — the lexer cannot know where it ends. | — |
| `QUOTED-IDS` | ruled | A quoted token in any id position is a line error, with one wording across every id position. | Ids were handled inconsistently, most positions silently accepting quotes; the corpus showed zero legitimate uses. | — |
| `LINK-OPERATOR-IN-IDS` | ruled | The two-dash link-operator sequence may not appear inside any id, at any id position. | Any input admitting two legal readings must be reported as an error, never resolved by a greedy guess. Measured cost of the ban was zero. | — |
| `SEMICOLON-STATUS` | ruled | The semicolon is reserved for a possible future statement separator; a bare semicolon outside a quoted string, an edge label, a comment, or a table row is a line error naming the reservation. | The reservation had been stated too weakly and went unverified. The edge-label exemption is necessary — real documents use the character as ordinary punctuation there. | — |
| `POSITIONAL-LIST-SPELLING` | ruled | A comma-delimited single token is the sole spelling for positional lists; the space-separated forms are retired. | A rest-of-line list can never gain a trailing option and cannot be written down honestly without a terminator. Two forms accepting identical input gave authors two attractors with no signal for which was canonical. | A workload objection preserved both forms in an earlier round and was overridden on re-weighing. Auto-numbering was rejected outright. |
| `COMMA-LIST-WHITESPACE` | ruled | Every comma-delimited list is one whitespace-free token. | Trimming whitespace was rejected because whitespace is the only available terminator for a variable-length positional list; trimming would remove the ability ever to add a trailing option. | — |
| `OPTION-POSITION-PARSING` | ruled | Option position is free on every directive without exception. | Two directives tested quotedness on the raw token stream while reading values from the option-stripped stream, rejecting legal lines with misleading messages. A parser must not test one projection of a line and read from another. | — |
| `POSITIONAL-VS-NAMED-ARGUMENTS` | open | Whether a positional argument may also be written as a named option is unsettled. | Both spellings are defensible and the corpus has not yet shown which authors reach for. | — |
| `POSITIONAL-FLAG-SPELLING` | open | Whether bare positional flags should become option keys carrying a value is unsettled. | A flag can say only that something is true, never why — but converting them all has costs not yet measured. | — |
| `GRAMMAR-SKETCH-COMPLETENESS` | ruled | Every nonterminal used in the grammar sketch is defined in the specification or imported from the standard core rules; the sketch stays an explicit sketch, with per-directive arity and genre allowlists specified in prose. | An incomplete grammar sketch leaves implementers guessing about undefined nonterminals. | — |
| `TYPED-BLOCK-SILENT-FALLBACK` | ruled | Silent fallback, truncation and last-wins behaviours in typed-block parsing are explicit line errors instead. | Silent fallback contradicts the closed-grammar, no-silent-failure discipline. | — |
| `DUPLICATE-LINE-DIAGNOSTIC-WORDING` | ruled | (uncited: the decision is a diagnostic's wording, which the engine writes rather than the normative text cites) The diagnostic for a repeated `flow` directive reads `duplicate flow directive`. The rest of the family — `duplicate title line`, `duplicate layout line` — keeps the *line* construction, and the editor helper that shared the phrase was renamed with it. | Everywhere it appeared, *flow line* meant the source line carrying the `flow` directive. Once `flowline` is a keyword in `flowchart`, where `flow` also exists, the message acquires a second reading — a duplicate flowline — and that reading names something which is not an error at all. Two spellings one space apart inside one genre, one of them describing a legal construct as illegal, is worth a rename; the author who most needs the message is the one who has just learned the new word. | Keeping the wording and relying on context — rejected; the error case and the legal case are one space apart. Renaming the whole family was rejected too: `title` and `layout` collide with nothing, and moving them would touch goldens and specification text for two messages that have no defect. The cost was one conformance golden, six specification files and one internal identifier, all inside an unreleased version, so no published document ever carried the old string. |
| `XML-CHARACTER-LEGALITY` | ruled | An artifact is an XML document, and XML forbids a fixed set of code points OUTRIGHT — unwritable literally and unwritable as a character reference, so no escape rescues them. A source containing one is now a parse-time line error naming the code point, refused before anything is drawn, rather than passed through into markup no conforming XML reader will open. The refused set is XML's own — `U+0000`–`U+0008`, `U+000B`, `U+000C`, `U+000E`–`U+001F`, `U+FFFE`, `U+FFFF`, an unpaired surrogate — and explicitly does NOT reach tab, newline, carriage return, `U+007F` or the C1 range, which stay legal. | An adversarial probe of every label surface, and every quoted string in the shipped corpus, found zero escaping holes under structural XML parsing — but a raw illegal code point passed the parser and rendered clean into an `.svg` no conforming reader would open, unreadable by the machine reader the format exists to serve, with no gate anywhere naming the defect because every document in the corpus happened to be clean. This is a well-formedness defect, not an injection: no markup is created by an illegal character. | Leaving the gap and documenting it as a caller responsibility — rejected, because the resulting artifact is not conformant XML at all, which is a stronger failure than an unsanitised-but-well-formed one. No escaped or mechanically substituted form is offered, because none exists: the fix is deleting the character or writing its code point as text. Reopens only if a future XML profile changes the forbidden set. |
| `GRAMMAR-LAYERING-MODEL` | ruled | The grammar is layered on **two axes, not one**. **Scope** answers *whose rule is it* — core, genre, profile — with the layout namespace a **sub-layer of core** rather than a fourth layer. **Stage** answers *when does it apply* — Grammar, Context, Resolution, Semantic, Rendering — five named groupings over the eight normative processing stages, which stay normative underneath. The classified **unit is the construct**, and the carrier is two columns on the vocabulary-source record that already existed, one row per construct. | Neither axis alone answers *where did we diverge*: *this key takes one value set here and another there* is Context-at-genre, *a compact list contributed an element after reporting an error* is Grammar-at-genre, and *the renderer drew a band around a non-member* is Rendering-at-core. A one-axis report either leaves an implementer asking which document to read, or says "genre layer" about something that could be a lexer bug or a reading rule. **Ubiquity is not membership** — a key accepted at the top level of every genre is still not core — which is what makes the layout namespace a sub-layer rather than a peer: what differs is fixity against ubiquity, a distinction the core already draws for itself. | A new normative document — rejected, there is not enough rule to fill one. A second machine-readable registry — a second thing to keep true. Keyword occurrences as the unit — prose drifts, and 14% of it is not a rule at all. The conformance fixtures as the unit — a fixture pins a rule but is not one. **One honest objection is on the record rather than smoothed away**: one of the eight stages cannot fail, so grouping it under *Grammar* makes that name mean two things at once; the five names win because they are what a second implementer arriving from a standards background already expects, and a report may always name one of the eight instead. The stage grouping reopens if a second implementation reports that it cost a distinction the eight names would have kept; the carrier reopens if the classification is ever required to reach a rule with no vocabulary row. |
| `LAYER-CROSSING-RULES` | ruled | What a genre may and must not do, and what a profile may and must not, are each written down as one list in the normative text — and the four places the language crosses its own layering are **declared exceptions rather than repaired**. A genre may own subject vocabulary, rename the node and connector spellings while taking their grammar, keys and model shape exactly, reuse another genre's spelling with the header as disambiguator, own defaults, refuse a word with a diagnostic that gives the ground, and own option keys. It must not redefine a core keyword's meaning, touch the layout namespace, change the error model, add a line shape the core parser cannot tokenize, re-lex another genre's tokens, widen what a reading agent may conclude, or change the shape of the canonical model. | Nothing here is a new restriction; every clause restates a rule already in force, and three profiles each carried the profile prohibition in three different wordings, none of them the layer's. All four crossings are load-bearing. The core grammar enumerates the genre tokens and the language versions, because the header must be readable before the genre is known. A genre owns one of the core line production's alternatives, and 17% of the core grammar is genre-shaped, so calling that a violation would require a per-genre lexer and break the *readable before the genre is known* property. An **experimental** genre permanently constrains the **core** option-key namespace — the sharpest of the four, running in the direction nobody writes rules for, which is why the core now has a *must not* list of its own; it makes two invariants explicit: a constraint that flows upward carries its own reason to where it lands, and **a layer's status does not bound the reach of the constraints it imposes**. | Repairing any of the four — rejected; each behaves exactly as it did. **One sub-question is deliberately left unruled and is recorded as open in the normative text**: if the experimental genre whose lane alphabet reserves three option keys were ever withdrawn, does the reservation survive it? The reservation's own text says yes; the precedent where a key went with its keyword says no. Deciding today would be deciding for a future with no evidence in it, and the question is answerable the moment there is a withdrawal to answer it about — so the text carries the question, both readings, and the reason for not answering, and until then the reservation stands as written. **A fifth crossing found later is a defect until it is written down.** |
| `REGISTERED-KEY-VALUE-GRAMMAR` | ruled | A genre **may** give an already-registered option key a second value grammar, under four conditions all of which are required: the two registrations are **section-disjoint**, both are live, each is documented completely in its own genre document, and the registry row names both acceptors. A genre must not give a second value grammar to a key whose existing acceptor is legal in the same section, and must not do it silently — **an undeclared second grammar is the defect, not the second grammar.** | The case existed in the tree before the rule did. One key had carried two disjoint value sets across two genres for nine development states — mandatory on one of them, with a twelve-member vocabulary sharing no value with the other's single one — while the registry sentence said it was live on one genre only, which was simply false. The language had a stated rule for a genre reusing a **keyword** and no stated rule at all for this, and that absence was the gap; the key is the instance proving it was not hypothetical. This is a third arm of the existing declared exception, whose two existing arms are one spelling in two namespaces; here it is one spelling inside one namespace with two disjoint value grammars, which the surrounding text would otherwise read as a collision no genre boundary can excuse. | Renaming either half — recommended **against** rather than merely not done: each spelling is borrowed from its own source standard, so a rename would spend a borrowed spelling to buy tidiness and would move published corpora. The arm is a permission and not an invitation — a genre that can spell a key of its own should. Reopens if a second value grammar is ever proposed for a key whose acceptors are **not** section-disjoint, which is the case the four conditions exist to refuse. |
| `NORMATIVE-KEYWORD-DECLARATION` | ruled | The specification adopts the standard requirement-keyword convention **explicitly, once**, in a numbered subsection at the top of the core document, in the wording that carries the all-capitals caveat verbatim. The versioning chapter now points at that subsection instead of declaring for itself, and every document with its own status block carries a pointer sentence. A gate checks the three things a machine can: that the declaration exists in the declared place, that every all-capitals modal construction in the specification is one of the eleven declared spellings, and that the pointer sentences are present. **The audit the adoption creates is named as a debt in the same ruling**, with its denominator and its price stated beside the claim. | The discipline was already 71% correct in a sample; two of the eleven keywords were used in the tree and declared nowhere; and the caveat gives 779 lowercase modals a stated status for the first time. **The place is the load-bearing half**: the declaration had lived inside one chapter's opening paragraph, naming four of the eleven spellings and one of the two source documents, while four in five of the core's all-capitals occurrences sat outside it. Adopting the sentence turns every existing occurrence into a claim on the day it lands, so the debt is stated where the claim is rather than discovered later — **adopt-then-audit**, because *is this a correct requirement keyword* has no answer before the document says which definition of the word it means. | The older, shorter declaration wording — rejected on the record: it omits one of the eleven keywords its own source defines, and carries no capitalisation caveat, which is the whole subject of the newer one. Unifying the translated twins on one convention was refused in both directions, each twin now declaring its own, because a gate can check that the sentence exists and cannot check that a translation is faithful — and the gate says so. The gate's own first run found one **more** defect than the hand census had predicted, and the discrepancy is recorded rather than rounded to the prediction: a census run once by hand disagrees with a gate run on every build, and the gate is the one that keeps being right. |
| `EXTENSIBILITY-MECHANISMS` | ruled | The language's extensibility is a **named set of four mechanisms, reserved in the first version rather than built**: the version header together with the compatibility rules; the keyword-initial line grammar, where a new capability is a new keyword and an older parser reports the unknown one precisely instead of guessing; the `key=value` option slots, so a new attribute never disturbs the positional arguments already written; and the profile mechanism, where a new domain is a new profile and the core is untouched. The scope of a first version is set by **frequency** — the content that appears most often in real figures is served first — and reserving room for what is foreseeable is part of that same scope decision rather than a separate one. | Extensibility is not implemented extensions, and the two failures it sits between are both real: building the foreseen needs makes a first version large and riddled with special cases, which is the outcome a small stable core exists to avoid, while a syntax with no reserved room makes the first genuinely new need a breaking change. Naming the mechanisms as a **set** is the load-bearing half. *The language is extensible* is a sentiment and answers nothing; four named doors let a later proposal be answered by pointing at the one that already carries it, and force an argument for a fifth to argue against a written list instead of into a gap — which is exactly what happened when a vendor namespace was proposed and refused for not being among them. | Choosing first-version scope by technical interest rather than by a measured census of what real figures contain — rejected; the census is also what fixes the defaults (`DEFAULT-VALUE-SELECTION`), so the two would have had to disagree. Implementing the foreseen extensions up front — rejected as the large-surface failure above. The set reopens on a need measured that none of the four can carry: that is the case a fifth mechanism has to make, and `LANGUAGE-EXTENSION-POLICY` records the one attempt so far and why the measurement refused it. |
| `LANGUAGE-EXTENSION-POLICY` | ruled | The language stays **closed** at 1.0: no vendor keyword, no vendor option key, no lenient mode, no private-use range. The reservation that had promised a future experimental or vendor extension mechanism is **retired**; the ban on standard keywords and option keys beginning with the reserved prefix is **kept, permanently and unconditionally**. No Core / Registered Extension / Private Extension tier scheme is created. | The language already has four named extensibility mechanisms — the version header and its compatibility rules, the keyword-initial line grammar (*new capability = new keyword; old parsers report errors precisely*), the option slots, and the profile mechanism — and a vendor namespace is not among them. A census of 97 recorded wants for a spelling the language does not have found **not one** asking for a private or vendor construct: every one asks the language to grow a **public** spelling, which is the proposal gate's business rather than a namespace's. The 47 refusals among them were decided by **meaning**, not capacity, so a door would not have changed a single one — a prefixed spelling of a refused word reproduces the misreading with a prefix on it. The strongest instance argues the other way: 19 of 32 transitions in this repository carry two words in comments because the language has no keyword for them, and had a prefixed form been legal those nineteen lines would have parsed, the model would have been nineteen figures poorer with nobody noticing, and there would have been nothing to count. **A closed language is a demand-measuring instrument, and a door is the thing that breaks the instrument.** Retiring the promise costs nothing and keeping it is the most expensive of the options, because its whole cost is paid by the author who believes it. A tier scheme was declined because two of its three tiers would be empty and the third already exists as the construct-status split — **a registry with zero members is a promise with no subject**, which must then be maintained, versioned and honoured. | Retiring the reservation **whole** and releasing the prefix in the core — a coherent position, argued from a precedent where a reserved word was released because nothing was using it, and it is on the record with its reopen condition. It is declined on one ground only: the prefix acquired a real consumer in the family's sidecar, so releasing it would make the family's most visible prefix mean two opposite things. The closed language reopens only on *two or more independent parties measured to have **forked** the engine to add private vocabulary — forks, not feature requests — and measured to have diverged in ways a namespace would have prevented*: a feature request is evidence for the proposal gate, a fork is the only evidence for a door, and the census counts zero. The naming ban has **no** reopen condition. **What this does not claim**: the same census leaves 34 wants unruled, so a closed language carrying them is not proven — it is not yet refuted, and the ruling says the gate is working, not that the pressure is gone. |
| `RESERVED-PREFIX-ENFORCEMENT` | ruled | The reserved keyword prefix gets a named diagnostic at both of its call sites, keyword position and option-key position, and the message says three things: the prefix is reserved against the language's **own** vocabulary and is not an extension namespace; the language is closed, so it does not become legal by waiting; and where an extension may live instead. What the author wants is more vertical space, which is a rendering request. In the timing genre the axis IS a tick count, so a break there removes ticks that would otherwise be asserted. | The argument that the borrow costs nothing because both the spelling and the concept already exist in the language. Reopens if the genre gains a construct making vertical position denote a quantity — a duration constraint or an absolute timestamp — at which point a discontinuity has something to interrupt. |
| `SEQUENCE-PARTICIPANT-GROUPING` | ruled | `sequence` admits no participant-grouping construct; `group` keeps its scene-genre meaning and gains no sequence sense. The row entered as parity with a drawing tool and was never re-tested after the genre was re-scoped to real-figure coverage, so measured need is zero. Neither source has the construct — part decomposition decomposes ONE lifeline, and gates and the frame bound an interaction rather than a subset of its lifelines. Reopens on a count of real figures whose lifelines are drawn in labelled bands — the evidence any genre cell needs — and the re-proposal owes a contiguity check either way, because the false-band finding does not expire. |
| `SEQUENCE-CONTAINMENT-SCOPE` | ruled | Under `sequence` the containment key takes FIVE acceptors — `message`, `operand`, `lifeline`, `state` and `fragment` — its object is a fragment id or an operand id, and nesting is capped at ONE level for the genre's first version. | The state invariant and the combined fragment are both interaction fragments in the source model, and an operand contains interaction fragments, so the two added acceptors are containment the standard already has rather than a new sense of the key. The cap follows the precedent that one level is the whole of a first version's containment, and costs no measured figure. Reopens on a measured figure needing a second level of nesting, or on a ruling that a fourth or fifth acceptor is a new SENSE of the key. |
| `MESSAGE-ORDER-AND-STATE` | ruled | Closed. The language can now state message ORDER and per-participant STATE structurally: a message's place in the ladder's row order IS its place in time, and a state occurrence sits on its own lifeline between the two messages it falls between. The two figures that recorded the gap deliberately stay as they are, at their older header, with their ordinal labels and their honest-limit comments intact. | The closing condition the question set for itself was met — a genre landing that brings a ladder layout path with it. The gap had been a WRONG answer rather than an unstated one: an ordinal label is naming, not semantics, so a reading agent asked how many links join two participants answers with the number of labels, where the truth is one association carrying several segments in time. | Retiring the question's number, refused: a corrected citation to it stays correct. What remains open is a STATUS, not a construct — the genre is experimental and requires `figdown 0.4`, and which surface a portable figure may use is tracked by the genre's own status line. |
| `STATECHART-TRANSITION-TOTALITY` | ruled | A statechart document cannot assert that its transition function is total. A set of drawn transitions out of a state is not a claim that no other event exists there, nor that other events are deliberately ignored. An author for whom *every event is handled here* matters writes it as prose in a note on the state, or as a shared class meaning; a reading agent that finds no such note reports the drawn transitions and nothing about the undrawn. | The source standard's run-to-completion paradigm silently discards a dispatched event with no enabled transition and no matching deferral, and supplies no well-formedness rule requiring a disposition for every event in every state — so the undrawn case and the drawn-and-silently-ignoring case render identically as absence. Completion transitions and deferred events mean the event alphabet is not even enumerable in the borrowed vocabulary. | The mirror-image misreading, that an exhaustive-looking fan of transitions asserts totality; the genre already forecloses the converse, that an undrawn transition is forbidden. Reopens on a revision of the source standard requiring an explicit disposition for every event of a declared alphabet, or on the language adopting a construct that declares a closed, named event alphabet per machine. |
| `GENRE-SELECTION-PRECEDENCE` | ruled | Identity decides the genre: read the genre table down and stop at the first row that describes the figure AS A WHOLE. Where the two disagree and the document says nothing, identity wins. The two portability prices are also split and must not be substituted for one another: VERSION portability (the declared version moves off `0.1`, so an implementation pinned to an older language version cannot read the figure at all) is charged only by `statechart` and `sequence`; STATUS portability (the construct is experimental, outside the v0.1 conformance surface and the compatibility promise) is charged by every experimental genre, `topology` and `flowchart` included. | Measured: over 24 subjects read blind by three readers in two conditions, selection itself was answered correctly 66/66 in both — agents already pick the genre from the subject. The rule was followed and the rule was wrong, so the fix is a precedence rule rather than more instruction. Reopens on a re-measurement in which selection itself, not the trap rows, degrades. |
| `MESSAGE-OCCURRENCE-GRANULARITY` | open | A `sequence` message is modelled as ONE occurrence, with no separate send/arrival events — UML 2.5.1 §17.4.3.1's two-occurrence Message is a DECLARED SIMPLIFICATION, recorded on `vocabulary-sources.tsv`'s `message` row since the genre draft. Reopens on that count plus a spelling that survives both checks. |
| `MULTICAST-MESSAGE-DELIVERY` | open | `sequence` has no spelling for one transmission reaching several lifelines; the interim is a synthetic medium lifeline with one message in and one message out, recorded as N point-to-point messages plus a `class` naming them one broadcast. | The workaround OVERSTATES ITS SOURCE — it asserts a total order and a participant (the medium) the protocol does not have, the same confidently-wrong-reading-with-nothing-to-warn-a-reader shape that `BITFIELD-REPETITION-CONSTRUCT` was ruled to close. Any spelling must first pass the RULE 4.1 single-source check applied to this genre at `SEQUENCE-SOURCE-STANDARD`; ITU-T Z.120 has not yet been read for this question. Reopens on a source verdict under that condition plus the census pending at `MESSAGE-OCCURRENCE-GRANULARITY`. |
| `GENRE-GRADUATION-ORDER` | ruled | Experimental genres promote to normative **one at a time, not as a batch**, and a candidate is promoted ahead of 1.0 only if it has evidence the others lack — a completed vocabulary-source survey carrying a verdict, with its priority decisions already discharged. `topology` is named the pilot that exercises the promotion gate for the first time, ahead of 1.0; every other experimental genre stays experimental through 1.0, which states non-convergence and is a judgement on none of them. | Promotion is the irreversible move once the 1.0 compatibility promise binds, so the burden of proof sits on promoting, not on waiting. Promoting none and freezing the promotion procedure for later — rejected on cost, not on coherence: it would still run the machinery for the first time under the very promise it exists to protect. |
| `GENRE-STATUS-RECORD` | ruled | The genre-status table splits in two. The original table is **kept byte-for-byte in content and retitled as the v0.1 record**, with one added sentence saying plainly that it is a preserved snapshot rather than a claim about today, and pointing at its successor. A new **current** table states every genre the tree holds, with each one's status, the release it landed in and its minimum language version, every cell read off a statement that already existed. The gate that had merely printed a note about the stale table now **gates on the current one**, cross-checked two-way against the grammar's own genre production — a genre present on one side and missing from the other is a named failure, not a note. | The old table was never wrong: its lead sentence was scoped to v0.1, and every word in it was true of v0.1 the day it was written and remains true of v0.1 today. **The defect was the reading.** A document several minor versions on presented a six-genre table with no signal that a reader arriving after two later genres landed was looking at a historical snapshot — and a version-scoped record read as if it were current is a false claim about today even though every word of it was true when written. A statement that was true when written does not need correcting; it needs its scope kept visible. | Overwriting the table in place — rejected; it would destroy the historical fact of what the v0.1 surface actually was, to fix a reading problem that a label solves without deleting anything. The gate deliberately never reads the labelled snapshot: checking it against today's ground truth would be checking the wrong thing on purpose. The current table reopens as an ordinary gate failure — which is the point of the retarget — the moment a further genre lands without a matching row, or a row names a genre the grammar no longer has. | `MANIFEST-EXTENSION-NAMESPACE` | ruled | The sidecar's one extension door gets its meaning: the key is spelled **owner-prefixed**, the owner being a token that party controls and can be traced to — a domain label they hold, an organisation, a registered project name — and **there is no registry, no allocation and no application**. The reportable duty is the one worth naming separately: it generalises the profile verifier's own assertion from *our* verifier to *any* conforming consumer.
